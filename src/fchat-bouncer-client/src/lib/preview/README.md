# URL Preview System

The URL Preview System is an extensible architecture for handling different types of URL previews in the F-ChatBouncer application. It replaces the previous hardcoded image preview logic with a flexible system that can be easily extended for new URL types.

## Architecture

The system consists of three main components:

1. **PreviewManager** - Central coordinator that manages different previewers
2. **URLPreviewer** - Interface for individual preview handlers
3. **Previewers** - Specific implementations for different URL types

## Current Preview Types

### Image Previewer
- Handles image URLs (jpg, jpeg, png, gif, webp, bmp, svg)
- Creates image previews with click-to-open functionality
- Shows error message when images fail to load
- Customizable size and styling options

### Discord Previewer
- Handles Discord channel and invite URLs
- Creates branded preview cards with Discord styling
- Shows Discord icon and branding

### F-List Previewer
- Handles F-List character and profile URLs
- Creates branded preview cards with F-List styling
- Shows F-List icon and branding

### Generic Previewer (Fallback)
- Handles any URL that doesn't match other previewers
- Creates simple clickable links
- Used as fallback for unknown URL types

## Usage

The preview system is automatically integrated into the BBCode URL tag. When a URL is processed, the system:

1. Checks each registered previewer to see if it can handle the URL
2. Uses the first matching previewer to generate the preview
3. Falls back to generic link if no previewer matches

## Extending the System

To add support for a new URL type:

1. Create a new previewer class implementing `URLPreviewer`:

```typescript
export class MyCustomPreviewer implements URLPreviewer {
  canHandle(url: string): boolean {
    // Return true if this previewer can handle the URL
    return url.includes('mycustomsite.com');
  }

  generatePreview(url: string, displayText: string, options?: PreviewOptions): PreviewResult {
    // Generate HTML for the preview
    return {
      html: '<div>My custom preview</div>',
      type: 'mycustom',
      success: true
    };
  }

  getType(): PreviewType {
    return 'mycustom';
  }
}
```

2. Register the previewer with the manager:

```typescript
import { previewManager } from '@/lib/preview/previewManager';
import { MyCustomPreviewer } from './myCustomPreviewer';

previewManager.registerPreviewer(new MyCustomPreviewer());
```

3. Add the new type to the `PreviewType` union in `types.ts`:

```typescript
export type PreviewType = 'image' | 'discord' | 'flist' | 'mycustom' | 'generic' | 'none';
```

## Security Considerations

The preview system generates HTML that is rendered using React's `dangerouslySetInnerHTML`. This is safe because:

1. **URL Validation**: All URLs are validated before processing
2. **No User Input in HTML**: The HTML structure is generated by the previewers, not from user input
3. **Display Text Sanitization**: User-provided display text is handled safely by React's built-in XSS protection
4. **Controlled HTML Generation**: Only trusted previewers generate HTML content

The previewers do NOT escape HTML entities because the content is rendered via `dangerouslySetInnerHTML`, which expects unescaped HTML. Escaping would cause the HTML to be displayed as text instead of being rendered.

## Benefits

- **Extensible**: Easy to add new URL types
- **Maintainable**: Each previewer is self-contained
- **Consistent**: All previews follow the same interface
- **Fallback-safe**: Always provides a working link if preview fails
- **Customizable**: Options for styling and behavior
- **Type-safe**: Full TypeScript support
- **Secure**: Proper XSS protection while allowing HTML rendering
